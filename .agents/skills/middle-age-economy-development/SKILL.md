# MiddleAgeEconomySim の開発

1. 最新 main の SHA、未解決 Issue、進行中 PR（ドラフトを含む）、関連する過去の PR・検証結果を確認する。対象 SHA の [HLD](../../../wiki/High_Level_Design.md)、[LLD](../../../wiki/Low_Level_Design.md)、コード、テストを突き合わせる。取得できた情報と未確認の情報を記録する。
2. 依頼で対象が指定されていれば、その Issue を進める。日次開発で選定を任された場合は、独立して検証できる未解決 Issue を1件選ぶ。適切なものがなければ過去の提案を現行コードと照合し、必要に応じて一つの達成条件に絞った Issue にする。進行中 PR との重複や未マージの前提を確認する。
3. [貢献ガイド](../../../CONTRIBUTING.md) に従って最新 main から作業ブランチを作る。コード変更では既存の公開 API と日次入口を確認し、回帰条件を検証する。資金・在庫・価格・失敗のレビュー観点は同ガイドに従う。
4. [ビルド・検証手順](../../../CONTRIBUTING.md#ビルドと検証) を実行する。依存取得に失敗した場合は同じ GoogleTest 版のローカルソースを指定できる。実行したコマンド、対象 SHA、環境、終了コード、テスト結果とログを記録する。利用できない環境や実行できなかった検証は明記する。
5. コード変更では新規サブエージェントに対象 SHA を渡し、変更を独立レビューさせる。テストや CLI の再現結果、指摘と対応を記録する。GUI を変更した場合はスクリーンショットも確認する。独立レビューを実施できない場合はレビュー待ちとして記録する。
6. 作業日（JST）、関連 Issue、達成条件、変更内容、対象コミット、検証結果と未検証項目、残作業を含むレビュー用ドラフト PR を準備する。日次開発では題名を `[日次開発]` で始める。レビュー待ち、マージ済み、検証のみ完了、保留を証拠に基づいて記録する。通知や報告期間は当該実行の指示に従い、マージ等の一時的な許可は指定された範囲でのみ適用する。
